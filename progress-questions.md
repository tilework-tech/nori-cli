# progress-questions.md — nori cloud → handroll shim, Part 2 (append-only)

- DECISION: spec §2.2 says delete `[cloud]` config outright, but the post-implementation revision (authoritative, later) requires translating the CLI's broker-URL config into `NORI_BROKER_URL` at spawn. Resolution: keep `CloudConfigToml`/`NoriConfig.cloud_broker_url` as a READ-ONLY field for translation; delete `save_cloud_broker_url`, the interactive URL prompt, and the `--broker-url` flag.
- DECISION: the handroll adapter is pinned via the existing data-driven agent registry, not a parallel connection type: `nori cloud` builds an `AgentConfigToml { slug: "nori-cloud", distribution.local { command: <resolved binary>, args: ["cloud-acp"], env: { NORI_BROKER_URL? } } }`, passes it through a clap-skipped `TuiCli` field, and forces `agent = "nori-cloud"` AFTER flag merging (the --agent guard). The child then rides the ordinary local-agent spawn path end to end — no cloud branches anywhere downstream.
- DECISION: graceful teardown (close stdin → wait → kill) is implemented generically in `SacpConnection::shutdown()` for ALL local ACP agents, not gated to cloud. Well-behaved agents exit in milliseconds on stdin EOF, so the ≥25s grace only bites for hung children. `Drop` keeps the SIGKILL process-group backstop for non-shutdown paths.
- ASSUMPTION: closing child stdin is achieved by aborting the connection task (it owns the transport, which owns the stdin writer; abort → drop → EOF). Pinned by a test using a child that writes a marker file after stdin EOF before exiting.
- DECISION: child-exit watching is a new `ConnectionEvent::ChildExited { status, stderr_tail }` emitted by a watcher task that owns the `Child` (takes over wait/reap); shutdown/Drop kill via the recorded pid/pgid instead of a shared `Child` handle. The backend relay turns an unexpected ChildExited into a loud `ErrorEvent` carrying the stderr tail — this replaces the old `is_cloud`-gated disconnect notice for every agent.
- DECISION: stderr surfacing = stderr task keeps a bounded tail buffer (in addition to log-file warns); spawn/initialize failures and ChildExited append the tail to the error text BEFORE `categorize_acp_error`, so handroll's "not authenticated — run: nori-handroll login" hits the Authentication category instead of "agent may be incompatible".
- VERIFIED: `mock_acp_agent` exits 0 on stdin EOF — wrapper-script fixtures (exec mock agent, write marker after it exits) are viable for teardown tests.
- UNKNOWN (baseline, RESOLVED): first `cargo test -p nori-acp` on the untouched worktree showed 14 failures in backend::tests::part3-area tests; cause was the `mock_acp_agent` binary not yet built when the run started (built mid-run). Re-run with the binary present is fully green — worktree gotcha: build `mock-acp-agent` before running nori-acp tests.
- DECISION (from test-quality review): the grace-kill test now asserts `elapsed >= grace` (otherwise today's instant-SIGKILL trivially passes); the child-crash fixtures use trigger files instead of fixed sleeps (race on loaded runners); the graceful-release e2e asserts the marker BEFORE dropping the PTY (closing the master can SIGHUP the child mid-shutdown → false failure); added a child-dies-mid-session e2e so the ChildExited→user path can't ship as a swallowed event.
- DECISION: hard requirement 2 is pinned at TWO boundaries: connection layer (ChildExited event with stderr tail) and user layer (e2e: TUI shows "exited unexpectedly" + the child's stderr, not a hang).
